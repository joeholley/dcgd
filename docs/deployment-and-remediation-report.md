## 2. Issues Encountered & Remediation Matrix

During the deployment lifecycle, several architectural, configuration, permission, and pipeline challenges were diagnosed and remedied:

| # | Issue Encountered | Root Cause Analysis | Remediation & Architectural Fix |
|---|---|---|---|
| **1** | **Legacy Synthetic Data Generator Invoked by Default** | `deploy-demo.sh` previously triggered Step 3 scripts (`generate-players.sql.tftpl`, `populate-player-tables.sql.tftpl`) targeting `gaming_raw.gcp_players`. | Quarantined all legacy in-repo BigQuery generators under `src/retail-data-and-ai-demo/infrastructure/terraform/games/legacy-data-gen/`. Gated legacy execution behind `--enable-legacy-data-gen` (default `false`). Configured runtime to consume `gaming_player_data.player_dna` (50M records). |
| **2** | **Hardcoded Table & Dataset Names** | Static table identifiers (`gcp_players`, `live_session_events`, `iap_transactions`, `neonvortex`) were present across configuration files and defaults. | Refactored `dataSourceConfig.ts`, `data_source_config.py`, `deploy-demo.sh`, and `cloudbuild.yaml` to dynamically resolve source tables at runtime from environment variables (`SOURCE_PLAYER_DNA_TABLE`, `SOURCE_RAW_EVENTS_TABLE`, `SOURCE_PAYMENT_SETTLEMENTS_TABLE`). Default substitutions set to empty strings. |
| **3** | **Local Workstation Deployment Attempts** | Multi-agent teams and developers attempted local `./deploy-demo.sh` execution, risking workstation environment divergence and lack of reproducible build artifacts. | Enacted mandatory Cloud Build policies: **Rule 0** in `.agents/rules/deployment-and-build-rules.md` and **Rule 7** in `.agents/AGENTS.md`. All builds and deployments must be executed via `gcloud builds submit --config=cloudbuild.yaml`. |
| **4** | **Cloud Build IAM Permission Denied on Cloud Run** | Cloud Build default compute service account (`996606880321-compute@developer.gserviceaccount.com`) lacked `roles/run.admin` and `roles/iam.serviceAccountUser` to deploy container revisions in Step 5. | Granted `roles/run.admin` and `roles/iam.serviceAccountUser` to the compute service account via IAM policy binding, enabling seamless automated deployment from Cloud Build. |
| **5** | **Deployments Without Dataset Context (Unconfigured Deployments)** | Running deployments without explicit arguments previously guessed or defaulted to legacy datasets. | Implemented **Step 0 Discovery Gate** in `cloudbuild.yaml` and `deploy-demo.sh` querying `INFORMATION_SCHEMA.TABLES` for both `player_dna` and per-game `raw_events` datasets, printing recommended commands, and exiting cleanly code 1. |
| **6** | **YAML Parser Error on Heredoc String in Cloud Build** | Unindented `cat <<EOF` in multiline bash step broke Cloud Build YAML parser. | Replaced heredoc with sequential `echo` statements for dynamic environment variable injection into `/workspace/env_vars.txt`. |
| **7** | **Legacy Mode Suggestions in Discovery Output** | Discovery gate output suggested deprecated legacy data generation commands to deployers. | Removed all legacy mode suggestions from `cloudbuild.yaml`, `deploy-demo.sh`, and `README.md`, leaving only pure-consumer lakehouse deployment workflows. |

## 3. Upstream Dataset Discovery Mechanism

When `cloudbuild.yaml` is submitted without explicit dataset substitutions, Step 0 acts as a safety gate:

1. **Global Demographic Discovery**: Queries `INFORMATION_SCHEMA.TABLES` for `table_name = 'player_dna'`, identifying `gaming_player_data.player_dna`.
2. **Per-Game Telemetry Discovery**: Queries `INFORMATION_SCHEMA.TABLES` for `raw_events` in `gaming_%` datasets.
3. **Command Generation**: Outputs ready-to-run Cloud Build command lines for:
   - Single target game dataset (`_GAME_DATASET=<DATASET>`)
   - All discovered game datasets (`_GAME_DATASETS="ds1,ds2,ds3..."`)
   - Granular explicit table substitutions (`_SOURCE_RAW_EVENTS_TABLE=...`, `_SOURCE_PLAYER_DNA_TABLE=...`)
4. **Clean Exit**: Exits with code 1 so the deployer can choose their target dataset without accidental deployment to incorrect environments.

```bash

gcloud config set project datacloudgamesdemo006
```
