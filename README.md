# Agentic Data Cloud - Unified Gaming Data, AI Governance & Executive Operations Platform

This repository reconciles three game analytics projects into a single, unified enterprise demonstration platform:

1. **Target Backend Architecture & Data Generator (`retail-data-and-ai-demo`)**: Provisions GCP infrastructure, Pub/Sub direct BigQuery streaming subscriptions, stored procedures, and BigQuery ML (BQML) churn prediction models.
2. **OmniArcade Governance & Vertex AI Agent Engine (`gamingdatademo`)**: Transforms raw telemetry into Gold feature tables via Dataform, enforces Dataplex Knowledge Catalog custom aspect tags & business glossaries, and deploys `google-adk` proactive agents.
3. **Player 360 Executive Operations Dashboard (`remix-gaming-app`)**: React 19 / Vite / Express platform featuring ADC authentication, real-time SSE event hub, knowledge catalog automatic rule discovery, and split-screen LiveOps churn guardrail simulator.

## 🚀 Automated Deployment via Google Cloud Build

All deployments are executed in Google Cloud via **Cloud Build** with dynamic table discovery:

```bash
# 1. Set your target GCP Project ID and region
gcloud config set project YOUR_PROJECT_ID
export GOOGLE_CLOUD_PROJECT=YOUR_PROJECT_ID
export GCP_LOCATION=us-central1

# 2. Authenticate with Google Cloud Application Default Credentials (ADC)
gcloud auth application-default login

# 3. Run Discovery Mode (discovers available upstream game datasets and player_dna table)
gcloud builds submit --config=cloudbuild.yaml

# 4. Deploy using the recommended game dataset substitutions
# Option A: Deploy targeting a single game dataset
gcloud builds submit --config=cloudbuild.yaml \
  --substitutions=_GAME_DATASET=<DISCOVERED_GAME_DATASET>,_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1

# Option B: Deploy targeting ALL discovered game datasets
gcloud builds submit --config=cloudbuild.yaml \
  --substitutions=_GAME_DATASETS="<DATASET_1>,<DATASET_2>,<DATASET_3>",_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1
```

### Accessing the Public Cloud Run Application

Cloud Build compiles the container images and deploys the unified application to **Cloud Run** (`--allow-unauthenticated`).

Once deployment completes, access the public HTTP endpoint URL:
```bash
# Get service URL directly via gcloud
gcloud run services describe gaming-demo-app --region=us-central1 --format='value(status.url)'
```

## 🏛️ Lakehouse Architecture & Table Drift Immunity

This platform operates as a **pure downstream consumer** of upstream player populations and game telemetry events generated by external tools (`generator` and `eventsim`). 

### Zero Hardcoding (Drift Immunity)
To protect against schema or naming drift between legacy setups and evolving upstream generators, **no source table is hardcoded**. Table substitutions default to empty strings, triggering BigQuery dataset discovery:

| Environment Variable | Cloud Build Substitution | Terraform Variable | Dynamic Discovery Target | Description |
| :--- | :--- | :--- | :--- | :--- |
| `SOURCE_PLAYER_DNA_TABLE` | `_SOURCE_PLAYER_DNA_TABLE` | `source_player_dna_table` | `<PROJECT_ID>.<DISCOVERED_DATASET>.player_dna` | Discovered upstream player population |
| `SOURCE_RAW_EVENTS_TABLE` | `_SOURCE_RAW_EVENTS_TABLE` | `source_raw_events_table` | `<PROJECT_ID>.<DISCOVERED_DATASET>.raw_events` | Discovered per-game raw event stream |
| `SOURCE_PAYMENT_SETTLEMENTS_TABLE` | `_SOURCE_PAYMENT_SETTLEMENTS_TABLE` | `source_payment_settlements_table` | `<PROJECT_ID>.<DISCOVERED_DATASET>.payment_gateway_settlements` | Discovered payment clearing feed |
| `BIGQUERY_DATASET_SILVER` | N/A | `silver_dataset_id` | `gaming_silver` | Downstream conformance & SRE views |
| `BIGQUERY_DATASET_GOLD` | N/A | `gold_dataset_id` | `gaming_gold` | Downstream analytical marts & Player 360 |
| `BIGQUERY_DATASET_REFERENCE` | N/A | `reference_dataset_id` | `gaming_reference_data` | Reference configurations & releases |
| `PUBLISHER_NAME` | `_PUBLISHER_NAME` | N/A | `Jingle Games` | Studio branding substitution |

### Deprecated Legacy Tables vs. Active Architecture
Previous iterations of the demo generated synthetic data in-repo. All legacy tables and routines are **deprecated and quarantined**:
- ❌ **Deprecated**: `gaming_raw.gcp_players`, `synthetic_players` $\rightarrow$ ✅ **Active**: `<discovered_player_dna_table>` (`SOURCE_PLAYER_DNA_TABLE`)
- ❌ **Deprecated**: `gaming_raw.live_session_events` $\rightarrow$ ✅ **Active**: `<discovered_game_dataset>.raw_events` (`SOURCE_RAW_EVENTS_TABLE`)
- ❌ **Deprecated**: `gaming_raw.iap_transactions` $\rightarrow$ ✅ **Active**: `<discovered_game_dataset>.payment_gateway_settlements` / `gaming_silver.silver_microtransactions`
- ❌ **Deprecated**: `gaming_silver.server_latency` $\rightarrow$ ✅ **Active**: `gaming_silver.silver_client_sre_metrics`
- ❌ **Deprecated**: `gaming_gold.gold_campaign_analytics` $\rightarrow$ ✅ **Active**: `gaming_gold.gold_marketing_roas_cohorts`

### Per-Game Telemetry Datasets & Discovery Workflow
Upstream `eventsim` runs generate telemetry on a **per-game dataset basis** (`gaming_<title>_<id>.raw_events`). Global player demographics reside in `gaming_player_data.player_dna` (or discovered `player_dna` table).

* **Discovery Mode (Default)**: Submitting `cloudbuild.yaml` without `_GAME_DATASET` or `_SOURCE_RAW_EVENTS_TABLE` will automatically query BigQuery for all available per-game datasets and the `player_dna` table, print the exact command lines to re-run (single-game or multi-game), and exit.
* **Deploy with Discovered Datasets**:
  ```bash
  # 1. Deploy targeting a single game dataset
  gcloud builds submit --config=cloudbuild.yaml \
    --substitutions=_GAME_DATASET=<DISCOVERED_GAME_DATASET>,_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1
  
  # 2. Deploy targeting ALL discovered game datasets
  gcloud builds submit --config=cloudbuild.yaml \
    --substitutions=_GAME_DATASETS="<DATASET_1>,<DATASET_2>,<DATASET_3>",_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1
  
  # 3. Or with granular explicit table substitutions
  gcloud builds submit --config=cloudbuild.yaml \
    --substitutions=_SOURCE_RAW_EVENTS_TABLE=<GAME_DATASET>.raw_events,_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1
  ```

### Strict Ground-Truth Air-Gap Invariant
- Upstream tools write simulation configuration into `gaming_player_data.simulation_parameters`.
- **Air-Gap Rule**: Application gateways (`server.ts`, `app.py`), UI dashboards, diagnostics monitors, and AI agents must **NEVER** read from or reference `gaming_player_data.simulation_parameters` (or `v_latest_simulation_parameters`).
- All KPIs, features, and insights are computed bottom-up from conformed lakehouse tables (`gaming_silver.*` and `gaming_gold.*`).
- The simulation registry is reserved solely for headless CI/CD test oracles (`tests/test_simulation_reconciliation.py`).

## 💻 Manual Step-by-Step Deployment

If you prefer to run or test individual components manually:

### Step 1: Provision Core Infrastructure (Terraform)
> **Note**: Required GCP APIs (`pubsub`, `bigquery`, `dataplex`, `datalineage`, `dataform`, `run`, `cloudbuild`, `aiplatform`) and the Cloud Run runner service account (`gaming-runner-sa`) are automatically enabled and created when `industry_target=games` is set.

```bash
cd src/retail-data-and-ai-demo/infrastructure/terraform
terraform init
terraform apply -var="project_id=YOUR_PROJECT_ID" -var="industry_target=games" -auto-approve
```

### Step 2: Configure & Run Governance & Dataform Pipeline

```bash
cd src/gamingdatademo/scripts

# Create config.json (or rely on GOOGLE_CLOUD_PROJECT & GCP_LOCATION env vars)
cat <<EOF > config.json
{
  "project_id": "YOUR_PROJECT_ID",
  "project_number": "YOUR_PROJECT_NUMBER",
  "region": "us-central1",
  "multi_region": "us"
}
EOF

# Run Dataform pipeline
cd ../dataform
npx --yes @dataform/cli run . --vars=project_id:YOUR_PROJECT_ID,industry:games

# Register Dataplex Glossaries & Aspect Tags
cd ../scripts
python3 01_create_glossary.py
python3 08_create_churn_guardrail_aspects.py
python3 07_create_lineage.py
```

### Step 3: Build & Deploy Container to Public Cloud Run

```bash
# Build unified container image via Cloud Build
gcloud builds submit --config=cloudbuild.yaml \
  --substitutions=_LOCATION=us-central1,_REPOSITORY=gaming-demo-images .

# Deploy to Cloud Run (Public/Unauthenticated mode)
gcloud run deploy gaming-demo-app \
  --image="us-central1-docker.pkg.dev/YOUR_PROJECT_ID/gaming-demo-images/gaming-app:latest" \
  --region=us-central1 \
  --service-account="gaming-runner-sa@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
  --allow-unauthenticated \
  --port=8080
```
