# Agentic Data Cloud — Gaming Platform (`dcgd`) Skill

## Overview & Ecosystem Role

This repository (`dcgd`) reconciles three game analytics and AI projects into a single, unified enterprise demonstration platform deployed to **Google Cloud Run** (`gaming-demo-app`):

1. **Target Backend Infrastructure (`src/retail-data-and-ai-demo`)**: Terraform modules (`industry_target = "games"`) provisioning Cloud Pub/Sub (`gaming-live-telemetry`) direct BigQuery subscriptions, Silver/Gold Medallion views, BigQuery ML (`gaming_player_churn_model`), Dataplex aspect types, Firestore Native DB, and `gaming-runner-sa`.
2. **OmniArcade Governance & Agent Engine (`src/gamingdatademo`)**: Dataform SQLX pipelines (`dataform/definitions/`), Dataplex Knowledge Catalog business glossaries and aspect tags (`scripts/`), Vertex AI Agent Engine (`google-adk`) deployments, and the internal Python Flask service (`website-live/app.py`) running on `127.0.0.1:5000`.
3. **Player 360 Executive Operations Cockpit (`src/remix-gaming-app`)**: React 19 / Vite / Tailwind UI and Express gateway (`server.ts`) listening on `0.0.0.0:8080`, providing real-time SSE streaming (`/api/guardrail/events`), <300ms LiveOps churn guardrails, OmniArcade AI chat (`/api/chat`), Automatic Rule Discovery (`/api/catalog/rules/discover`), and HTTP/WebSocket (`/api/ws`) reverse proxying to the internal Flask app.
4. **Proactive ADK Agents (`src/agents`) & Telemetry Simulator (`src/simulator`)**: Contains the `anomaly` and `kc` ADK agent implementations and local telemetry simulation utilities.

## Core Architectural Invariants (Mandatory Rules)

1. **Pure Downstream Consumer & Table Drift Immunity (Zero Hardcoding)**:
   - Consumes upstream `player_dna` (generated by `generator`) and per-game `gaming_<title>_<id>.raw_events` + `payment_gateway_settlements` (generated by `eventsim`).
   - **Never hardcode** source or medallion table names in SQL queries, routes, or UI components. Always resolve table names dynamically via `dataSourceConfig.ts` (`getTableMapping()`) in TypeScript and `data_source_config.py` (`get_table_mapping()`) in Python.
   - All legacy tables (`gaming_raw.gcp_players`, `live_session_events`, `iap_transactions`, `server_latency`, `gold_campaign_analytics`) and in-repo SQL generators are deprecated and quarantined under `legacy-data-gen/`.
2. **Strict Ground-Truth Air-Gap**:
   - Runtime code (`server.ts`, `app.py`), UI dashboards, diagnostics monitors, and AI agents must **NEVER** query or reference `gaming_player_data.simulation_parameters` (or `v_latest_simulation_parameters`).
   - All KPIs and ML features are computed bottom-up from conformed `gaming_silver.*` and `gaming_gold.*` tables.
3. **Upstream Per-Game Discovery Exit**:
   - Submitting `cloudbuild.yaml` (or running `deploy-demo.sh`) without `_GAME_DATASET`, `_GAME_DATASETS`, or `_SOURCE_RAW_EVENTS_TABLE` (and with `_ENABLE_LEGACY_DATA_GEN=false`) triggers **Discovery Mode**: it queries `INFORMATION_SCHEMA.TABLES` for `player_dna` and `gaming_%` datasets containing `raw_events`, prints exact deployment commands, and exits immediately (`exit 1`).
   - **Never** auto-select a game dataset or bypass the discovery exit without explicit user instruction.
4. **Cloud Build Only & Container Runtime Rules**:
   - **Never** run full deployments (`deploy-demo.sh`) directly from a local shell; always submit via `gcloud builds submit --config=cloudbuild.yaml`.
   - In `entrypoint.sh`, always run the Flask app via `gunicorn --bind "127.0.0.1:${PYTHON_PORT}" --workers 1 --threads 8 --worker-class gthread --timeout 300 app:app` (never `python3 app.py`).
   - In `gcloud run deploy`, pass `--port=8080` and include `PYTHON_PORT=5000` in `--set-env-vars` (**never** include `PORT` inside `--set-env-vars`, as `PORT` is reserved by Cloud Run).

For dual-process routing details, UI-to-backend endpoint mappings, the <300ms LiveOps Churn Guardrail pipeline, and the 8-step orchestrator runbook, see [references/architecture_and_routing.md](references/architecture_and_routing.md).

## Common Workflows & Commands

### 1. Pre-Flight Configuration & Invariant Validation
Before submitting a Cloud Build job or modifying runtime scripts, run the bundled pre-flight validator:

```bash
# Validate Cloud Build substitutions and verify repository invariants
python3 .agents/skills/dcgd/scripts/validate_dcgd_config.py \
  --substitutions "_GAME_DATASET=gaming_neonvortex_7491282640212123500,_SOURCE_PLAYER_DNA_TABLE=my-proj.gaming_player_data.player_dna,_LOCATION=us-central1" \
  --check-repo-files .

# Validate shell syntax of entrypoint.sh and deploy-demo.sh
bash -n entrypoint.sh && bash -n deploy-demo.sh
```

### 2. Automated Deployment via Google Cloud Build
```bash
# Step A: Run Discovery Mode (queries BigQuery for player_dna and per-game raw_events datasets, prints commands, and exits)
gcloud builds submit --config=cloudbuild.yaml --project="$PROJECT_ID"

# Step B (Option 1): Deploy targeting a single discovered game dataset
gcloud builds submit --config=cloudbuild.yaml \
  --project="$PROJECT_ID" \
  --substitutions=_GAME_DATASET=<DISCOVERED_GAME_DATASET>,_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1

# Step B (Option 2): Deploy targeting multiple discovered game datasets
gcloud builds submit --config=cloudbuild.yaml \
  --project="$PROJECT_ID" \
  --substitutions=_GAME_DATASETS="<DATASET_1>,<DATASET_2>",_SOURCE_PLAYER_DNA_TABLE=<DISCOVERED_PLAYER_DNA_TABLE>,_LOCATION=us-central1

# Retrieve the deployed public Cloud Run URL
gcloud run services describe gaming-demo-app --region=us-central1 --project="$PROJECT_ID" --format='value(status.url)'
```

### 3. Component-Level Infrastructure, Dataform & Dataplex Commands
When inspecting or testing individual sub-components in isolation:

```bash
# 1. Terraform infrastructure (src/retail-data-and-ai-demo/infrastructure/terraform)
terraform -chdir=src/retail-data-and-ai-demo/infrastructure/terraform init
terraform -chdir=src/retail-data-and-ai-demo/infrastructure/terraform validate

# 2. Dataform Medallion pipeline (src/gamingdatademo/dataform)
npx --yes @dataform/cli compile src/gamingdatademo/dataform \
  --vars=project_id="$PROJECT_ID",industry=games

# 3. Dataplex Glossary, Aspect Tags & Lineage registration (src/gamingdatademo/scripts)
python3 src/gamingdatademo/scripts/01_create_glossary.py
python3 src/gamingdatademo/scripts/08_create_churn_guardrail_aspects.py
python3 src/gamingdatademo/scripts/07_create_lineage.py
```
